TL;DR

Mixture-of-experts (MoE) models rely on expert parallelism, where every MoE layer dispatches hidden states to the activated experts and combines the expert outputs. As compute has outpaced interconnect bandwidth, this communication has become a major bottleneck. Because transformer blocks update the residual stream incrementally, we use a hidden state from an earlier layer as a reference and communicate only the compressed change. EchoMoE retrofits existing MoE models without retraining from scratch.

Problem: Communication bottleneck of expert parallelism

Mixture-of-Experts (MoE) models enable substantial growth in parameter count while keeping per-token computation modest through sparse expert activation. Serving frontier MoE models requires distributing experts across many GPUs using Expert Parallelism (EP).

At every MoE layer, each token's activation is sent to the devices hosting its selected experts (dispatch), and the expert outputs are sent back (combine). When the model spans multiple nodes, both transfers carry the full hidden state across the network. For DeepSeek-V3 served with 128 GPUs, these collectives account for 60% of transformer-layer latency, and still 32% after overlapping communication with computation. As accelerator compute grows faster than interconnect bandwidth, EP communication increasingly limits MoE throughput and latency.

Prior work either redesigns the architecture before pretraining, which cannot be applied to existing models, or reduces the cost of each communicated element through faster kernels or lower precision. Regardless of precision, every MoE layer still transfers all activation dimensions on both collectives.

Observation: Nearby MoE layers receive similar inputs

Each transformer block adds its output to the residual stream rather than overwriting it, so a token's hidden state changes gradually with depth and nearby MoE layers read highly similar inputs.

>90% mean cosine similarity between a token's inputs to adjacent MoE layers
>80% of the variance in the next MoE input is predictable from the previous one with a simple affine predictor

Yet standard EP still communicates the full activation at every layer, even when much of it is predictable from an earlier state. Given a cached activation from an earlier layer, we only need to communicate the change.

Method: Communicate the change

EchoMoE partitions the MoE layers into groups of $s$ consecutive layers. Full-width hidden states are transmitted once per layer group rather than at every MoE layer.

1Cache a reference

The first layer of each group is a reference layer. It broadcasts the full hidden state to every rank, which caches it as $z$. The broadcast is asynchronous and does not block the forward pass.

2Compress dispatch

The following $s-1$ layers reuse $z$. The owner rank compresses and dispatches only the difference between the current state $x_\ell$ and the scaled reference:

$$c_d = C_d\,(x_\ell - a \odot z)$$

Each expert rank reconstructs its input from the cached reference $z$ and the dispatched code $c_d$.

3Compress combine

Expert outputs are updates to the residual stream and can be represented in a lower-dimensional space. Each node returns a single compressed state, which the owner rank decompresses once.

All compressors and decompressors are linear, so they fold into the expert weights and add no extra serving-time operations.

Figure 2. Store once, reuse across layers. A reference is shared once per layer group, and every following layer communicates only the compressed change. Routing is unchanged.

Retrofitting an existing model

EchoMoE preserves the original model's behavior by first initializing the compressors to minimize activation reconstruction error, then training end-to-end to match the uncompressed model. This requires 8,500× fewer training tokens than full pretraining.

Results: Less RDMA traffic, higher throughput

We evaluate EchoMoE on Qwen3-30B-A3B across 18 benchmarks spanning knowledge & reasoning, mathematics, coding and instruction following, served with vLLM at EP32 on four H100 nodes.

Figure 3. Less communication translates directly into higher throughput. EchoMoE keeps task performance close to the uncompressed model and outperforms the plain compression baseline at every level of RDMA savings, while throughput rises steadily as more traffic is saved. Hover over a point for details.

EchoMoE reduces RDMA traffic by 58% with only a 3.8 pp drop in task performance, and improves throughput by 22.6%. Milder compression drops only 2.0 pp, and more aggressive compression improves throughput by 42.9%.

EchoMoE outperforms plain compression. At similar task performance, EchoMoE sends 26% less RDMA traffic than plain compression, which directly compresses dispatch activations.

Analysis: Reference states improve dispatch compression

Figure 4. The reference is what makes compression work. (a) Compressing the change loses far less than compressing the activation directly. (b) Refreshing the reference more often is the better use of bandwidth. (c) Decode gains grow with load.

  • Reference states substantially improve dispatch compression. At width 512, plain dispatch loses 21.1 pp, whereas reference dispatch loses only 2.6 pp.
  • Expert outputs are more compressible than dispatch activations, consistent with their lower-dimensional structure.
  • Smaller strides with narrower codes outperform larger strides with wider codes. Communication is better spent on more frequent references.

Inference: Where the speedup comes from

EchoMoE shortens prefill mainly by reducing communication. Prefill communication drops from 115 to 64 ms, while compression adds only a few milliseconds.

Figure 5. The speedup comes from communication. Communication time shrinks the most, while compression adds only a small cost.

Gains grow on slower networks

Figure 6. The slower the network, the larger the gain. Over Ethernet, EchoMoE improves throughput by up to 2.38× with BF16 and 3.24× with FP8 communication, while the same configurations give small gains on InfiniBand. Hover over the chart for each configuration.

Gains grow on slower networks. Over bandwidth-constrained Ethernet (about 23 Gb/s per node), EchoMoE improves inference throughput by up to 2.38×, and up to 3.24× with FP8 communication, paving the way for wide-area distributed inference.

Generality: Other MoE models

Applied to Gemma 4, Kanana-2, Nemotron-3.5 and Moonlight, EchoMoE roughly halves their RDMA traffic with a 2.4–5.9 pp task performance drop. EchoMoE also composes cleanly with FP8 quantization, with no additional loss in task performance.

Conclusion

EchoMoE exploits the cross-layer predictability of MoE inputs by caching an earlier activation as a reference and communicating only the compressed change. It establishes cross-layer predictability as a practical mechanism for substantially reducing EP communication in existing MoE models, and could also be incorporated as a novel architecture for pretraining.
